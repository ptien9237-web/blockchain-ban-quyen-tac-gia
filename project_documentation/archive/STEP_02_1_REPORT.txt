- Hệ thống mã mời tác giả (Author Invitation System) hoạt động với nguyên tắc bảo mật tối đa (Zero Raw Code Storage):
  * Sinh mã CSPRNG ngẫu nhiên chuẩn Node.js `crypto.randomBytes`.
  * Chỉ lưu chuỗi băm SHA-256 (`CodeHash`) vào CSDL SQL Server.
  * Chuỗi mã nguyên bản (`BKC-XXXX-YYYY-ZZZZ`) chỉ trả về duy nhất 1 lần khi tạo mã thành công để Admin sao chép.
  * API danh sách mã mời tuyệt đối không để lộ mã gốc lẫn CodeHash.
  * Transaction SQL Server sử dụng gợi ý khóa dòng `WITH (UPDLOCK, ROWLOCK)` ngăn chặn hoàn toàn race condition và tình trạng sử dụng vượt số lượt cho phép (`MaxUses`).
  * Người dùng đổi mã thành công lập tức được cấp vai trò `AUTHOR` và tự động làm mới `AuthContext`.

3. QUY TRÌNH CẤP MÃ MỜI VÀ ĐỔI QUYỀN TÁC GIẢ (AUTHOR INVITATION FLOW)
--------------------------------------------------------------------------------
A. Tạo mã mời (Chỉ ADMIN đã đăng nhập):
   1. ADMIN truy cập `/admin`, mở form "Tạo mã mời mới".
   2. Chọn thời hạn hiệu lực (7, 14, 30, 90, 180, 365 ngày), số lượt sử dụng tối đa (mặc định: 1) và ghi chú (tùy chọn).
   3. Backend xác thực session HttpOnly cookie + xác minh role ADMIN trong CSDL.
   4. Sinh mã ngẫu nhiên: `generateInvitationCode()` dùng `crypto.randomBytes(6)` -> Định dạng `BKC-XXXX-YYYY-ZZZZ`.
   5. Băm SHA-256 mã vừa tạo: `hashInvitationCode(rawCode)` -> chuỗi hex 64 ký tự `CodeHash`.
   6. Lưu bản ghi vào `dbo.AuthorInvitations` với `CodeHash`, `CreatedByUserId`, `ExpiresAt`, `MaxUses`, `UsedCount = 0`, `Status = 'ACTIVE'`.
   7. Backend trả về JSON:
      { "invitationId": "...", "code": "BKC-XXXX-YYYY-ZZZZ", "expiresAt": "...", "maxUses": 1 }
   8. Giao diện hiển thị Modal với mã đầy đủ và nút "Sao chép mã". Sau khi đóng modal, mã thô không thể xem lại.

B. Quản lý và thu hồi mã mời:
   1. ADMIN xem danh sách tại `/admin` (hiển thị thời hạn, số lượt đã dùng/tối đa, trạng thái).
   2. Khi cần, ADMIN bấm nút "Thu hồi" kèm hộp thoại xác nhận.
   3. Backend cập nhật `Status = 'REVOKED'`, `RevokedAt = GETDATE()`, `RevokedByUserId = @AdminId`.
   4. Mã bị thu hồi lập tức bị từ chối nếu có ai cố gắng nhập.

C. Đổi mã mời lấy quyền tác giả (Độc giả READER):
   1. Độc giả đăng nhập, vào trang Hồ sơ cá nhân (`/profile`).
   2. Giao diện hiển thị khối "Trở thành tác giả: Nhập mã mời".
   3. Độc giả điền mã (Ví dụ: `BKC-A1B2-C3D4-E5F6`) và bấm "Kích hoạt quyền Tác giả".
   4. Frontend gửi `POST /api/invitations/redeem` kèm `{ "code": "..." }`.
   5. Backend mở SQL Transaction:
      - Chuẩn hóa mã (trim, uppercase) và tính SHA-256 `CodeHash`.
      - Khóa dòng đọc: `SELECT TOP 1 * FROM dbo.AuthorInvitations WITH (UPDLOCK, ROWLOCK) WHERE CodeHash = @CodeHash`.
      - Kiểm tra tính hợp lệ:
        * Tồn tại bản ghi? (Nếu không -> Báo lỗi 400).
        * Trạng thái là 'ACTIVE'? (Nếu REVOKED hoặc EXHAUSTED -> Báo lỗi 400).
        * Chưa hết hạn: `ExpiresAt > GETDATE()`? (Nếu đã quá hạn -> Báo lỗi 400).
        * Còn lượt sử dụng: `UsedCount < MaxUses`? (Nếu đã hết -> Báo lỗi 400).
        * Người dùng đã là AUTHOR? (Nếu đã là AUTHOR -> Báo lỗi 400, không tiêu thụ lượt mã).
        * Người dùng đã từng đổi chính mã này chưa? (Kiểm tra `dbo.InvitationUses` -> Báo lỗi nếu trùng).
      - Thực thi cập nhật:
        * Tăng `UsedCount = UsedCount + 1`.
        * Nếu `UsedCount = MaxUses` -> Cập nhật `Status = 'EXHAUSTED'`.
        * Chèn bản ghi nhật ký kiểm toán vào `dbo.InvitationUses` (UserId, UsedAt, IpAddress, UserAgent).
        * Chèn bản ghi vai trò AUTHOR vào `dbo.UserRoles` (RoleId = 2).
      - Commit Transaction.
   6. Frontend nhận phản hồi thành công, gọi `refreshUser()` lấy lại hồ sơ từ `/api/auth/me`.
   7. `AuthContext` cập nhật `roles` sang `[READER, AUTHOR]`. Trang `/profile` tự động chuyển đổi sang giao diện tác giả, mở khóa tạo sách và quản lý tác phẩm.

4. DANH SÁCH CÁC API HOÀN THÀNH
--------------------------------------------------------------------------------
A. Phân hệ Quản trị (Admin - yêu cầu xác thực + role ADMIN):
   - GET   /api/admin/invitations
     * Mục đích: Lấy danh sách mã mời tác giả (phân trang page/limit, thống kê tổng số, trạng thái).
     * Bảo mật: Không trả về chuỗi mã thô và không trả về CodeHash.
   - POST  /api/admin/invitations
     * Mục đích: Tạo mã mời mới với thời hạn (1 - 365 ngày), số lượt (1 - 1000 lượt), ghi chú.
     * Bảo mật: Trả về chuỗi mã thô duy nhất 1 lần trong phản hồi này.
   - PATCH /api/admin/invitations/:id/revoke
     * Mục đích: Thu hồi mã mời đang hiệu lực.

B. Phân hệ Mã mời (User - yêu cầu xác thực):
   - POST  /api/invitations/redeem
     * Mục đích: Độc giả gửi mã mời để đổi lấy vai trò AUTHOR.
     * Bảo mật: Chống race condition với UPDLOCK/ROWLOCK, kiểm tra trạng thái/thời hạn, ghi nhật ký sử dụng, bảo toàn vai trò ADMIN nếu có.

C. Phân hệ Xác thực & Quyền hiện hành:
   - GET   /api/auth/me
     * Mục đích: Lấy thông tin tài khoản hiện tại kèm mảng quyền `roles` truy vấn trực tiếp từ `dbo.UserRoles`.
