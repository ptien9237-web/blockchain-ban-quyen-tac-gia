DANH MỤC KIỂM TRA BÀN GIAO DỰ ÁN BOOKCHAIN LIBRARY
(HANDOFF CHECKLIST & ARTIFACT SANITIZATION GUIDELINE)
================================================================================
Dự án: BookChain Library — Digital Library & Blockchain Copyright Registry
Phiên bản bàn giao: 1.0 (Production-Ready Architecture)
Ngày lập: 15/10/2026
Mục đích: Hướng dẫn người bàn giao (Sender) chuẩn bị gói mã nguồn sạch sẽ, đầy đủ
và tuyệt đối an toàn; đồng thời giúp người tiếp nhận (Recipient) kiểm đếm toàn diện
các thành phần trước khi đưa vào vận hành.

================================================================================
1. NGUYÊN TẮC BÀN GIAO CỐT LÕI
================================================================================
1. Bảo mật tuyệt đối: Không để lọt bất kỳ mật khẩu thật, khóa riêng tư (Private Key)
   cá nhân, API key của bên thứ ba, hay dữ liệu định danh cá nhân vào gói bàn giao.
2. Đầy đủ và tự cung ứng (Self-Contained): Người nhận có thể tái lập 100% môi trường
   từ trạng thái sạch chỉ với các tệp được bàn giao kèm `package-lock.json`.
3. Tách biệt tệp tái tạo được vs tệp kiến trúc: Loại bỏ các thư mục build/cache cồng
   kềnh (node_modules, dist, cache), nhưng BẮT BUỘC giữ lại các artifact blockchain
   đã được trích xuất (exported) mà mã nguồn TypeScript trực tiếp import.
4. Không chỉnh sửa project gốc: Việc dọn dẹp hoặc đóng gói bàn giao phải được thực
   hiện trên bản sao (staging copy) hoặc qua lệnh archive, không xóa tệp gốc.

4. NHỮNG GÌ TUYỆT ĐỐI KHÔNG GỬI / PHẢI LOẠI BỎ (CRITICAL EXCLUSIONS)
================================================================================
Người thực hiện bàn giao PHẢI KIỂM TRA KỸ và LOẠI BỎ các mục sau trước khi nén tệp:

[!] 4.1. File cấu hình môi trường chứa Secret thật:
    - LOẠI BỎ: `.env`, `.env.local`, `.env.production` (Chỉ gửi `.env.example`).
    - Lý do: Chứa mật khẩu tài khoản `sa` SQL Server của máy người bàn giao, khóa bí mật
      ký JWT token phiên làm việc, hoặc RPC key.

[!] 4.2. Khóa riêng tư (Private Keys) và Ví cá nhân:
    - LOẠI BỎ: Bất kỳ file nào lưu trữ Private Key của ví cá nhân có chứa tài sản thật
      trên Ethereum Mainnet hoặc testnet.
    - Ngoại lệ an toàn: Các Private Key của Hardhat Account #0 đến #19 (ví dụ khóa
      `0xac09...f2ff80`) là tài khoản thử nghiệm công khai nổi tiếng trong cộng đồng
      Ethereum/Hardhat, hoàn toàn không có giá trị thương mại và an toàn để ghi chú.

[!] 4.3. Các thư mục có thể tái tạo (Reproducible Directories - Giảm tải dung lượng):
    - LOẠI BỎ: `node_modules/` (~300MB - Người nhận chỉ cần chạy `npm install`).
    - LOẠI BỎ: `dist/`, `dist-ssr/` (Tái tạo bằng `npm run build`).
    - LOẠI BỎ: `cache/` (Tự sinh khi chạy `npm run contracts:compile`).
    - LOẠI BỎ: `artifacts/` (Tự sinh khi biên dịch hợp đồng thông minh).

[!] 4.4. Dữ liệu tệp tải lên và tệp tạm thời (Storage & Temp files):
    - LOẠI BỎ: Các tệp sách riêng tư do người dùng tự tải lên trong `storage/books/*`
      (Chỉ giữ lại tệp `.gitkeep` để duy trì thư mục rỗng).
    - LOẠI BỎ: Thư mục đệm IPFS cục bộ `storage/ipfs/*`.
    - LOẠI BỎ: Thư mục `.gemini/`, `scratch/`, `impeccable/` nếu có.

[!] 4.5. Tệp cấu hình IDE và Nhật ký hệ thống (Logs & OS Files):
    - LOẠI BỎ: `*.log`, `npm-debug.log*`, `yarn-error.log*`, `logs/`.
    - LOẠI BỎ: Thư mục cấu hình cá nhân `.vscode/` (ngoại trừ `.vscode/extensions.json`), `.idea/`.
    - LOẠI BỎ: Tệp rác của hệ điều hành: `.DS_Store` (macOS), `Thumbs.db`, `desktop.ini` (Windows).

[!] 4.6. Bản sao lưu CSDL chứa dữ liệu thật:
    - LOẠI BỎ: Các file sao lưu SQL Server (`*.bak`) có chứa thông tin khách hàng hoặc tài khoản cá nhân.
      (Người nhận sẽ khởi tạo database sạch từ script DDL `BookChainLibrary_SQLServer.sql`).

5. HƯỚNG DẪN TẠO GÓI BÀN GIAO SẠCH (CLEAN EXPORT / ZIP GUIDE)
================================================================================

5.1. Tạo bản sao lưu sạch bằng Git Archive (Nếu đang dùng Git):
  - Lệnh này sẽ tự động bỏ qua toàn bộ tệp nằm trong `.gitignore` (bao gồm `node_modules`, `.env`, `artifacts`, `cache`, `dist`):
      git archive --format=zip --output=BookChainLibrary_Handoff_v1.0.zip HEAD

5.2. Tạo gói nén thủ công trên Windows PowerShell:
  - Nếu cần tạo thủ công từ thư mục làm việc, hãy tạo một thư mục tạm `BookChain_Clean`,
    sao chép các tệp hợp lệ và nén lại:
    ```powershell
    # 1. Tạo thư mục tạm
    New-Item -ItemType Directory -Path "..\BookChain_Handoff_Staging" -Force

    # 2. Sao chép cây thư mục bỏ qua các thư mục rác
    robocopy . "..\BookChain_Handoff_Staging" /E `
      /XD node_modules dist cache artifacts .git .gemini scratch storage\books storage\ipfs `
      /XF .env *.log

    # 3. Tạo lại thư mục storage trống kèm .gitkeep
    New-Item -ItemType Directory -Path "..\BookChain_Handoff_Staging\storage\books" -Force
    New-Item -ItemType File -Path "..\BookChain_Handoff_Staging\storage\books\.gitkeep" -Force

    # 4. Đóng gói ZIP
    Compress-Archive -Path "..\BookChain_Handoff_Staging\*" `
      -DestinationPath "..\BookChainLibrary_Handoff_v1.0.zip" -Force
    ```

5.3. Bảng kiểm tra xác nhận trước khi gửi (Sender Pre-Flight Checklist):
  [ ] File `.env` thật đã được loại bỏ; file `.env.example` đã có mặt.
  [ ] Thư mục `node_modules/` đã được loại bỏ.
  [ ] Thư mục `dist/` và `artifacts/` đã được loại bỏ.
  [ ] File `deployments/localhost.json` đã có mặt.
  [ ] File `src/contracts/deployedAddresses.json` đã có mặt.
  [ ] File `server/contracts/deployedAddresses.json` đã có mặt.
  [ ] File `SETUP_GUIDE.txt` đã có mặt ở thư mục gốc.
  [ ] Dung lượng tệp nén `.zip` dưới 15MB (nếu vượt quá 50MB, chắc chắn bạn đã quên bỏ `node_modules`).
