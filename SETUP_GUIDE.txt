Tài liệu hướng dẫn từng bước cấu hình máy trạm, cơ sở dữ liệu, smart contract và
chạy toàn bộ các chức năng của BookChain Library từ trạng thái sạch (clean state).

Phiên bản: 1.0 (Hoàn thiện sau 5 giai đoạn kiến trúc + Refactor UI/UX + Author Approval)
Ngôn ngữ: Tiếng Việt
Hệ điều hành tương thích: Windows 10/11 (hỗ trợ Linux / macOS với các lệnh shell tương đương)

1.  Phần mềm và phiên bản yêu cầu

1. PHẦN MỀM VÀ PHIÊN BẢN YÊU CẦU
================================================================================
Trước khi bắt đầu, hãy đảm bảo máy tính của bạn đã cài đặt các phần mềm sau:

1.1. Node.js & npm:
  - Phiên bản Node.js: v24.x (Khuyến nghị v24.19.0 LTS hoặc tối thiểu Node.js >= 20.18.0).
  - Phiên bản npm: v11.x (Đã kiểm chứng với npm 11.17.0).
  - Kiểm tra bằng lệnh:
      node -v
      npm -v

1.2. Microsoft SQL Server:
  - Phiên bản: Microsoft SQL Server 2022 hoặc 2025 (Bản Developer hoặc Express Edition đều được).
    (Đã kiểm chứng thực tế: Microsoft SQL Server 2025 RTM 17.0.1000.7 X64 Developer Edition).
  - Công cụ quản trị: SQL Server Management Studio (SSMS v20+) hoặc Azure Data Studio, hoặc tiện ích dòng lệnh `sqlcmd`.
  - Chế độ xác thực: Mixed Mode Authentication (SQL Server and Windows Authentication mode).
  - Cổng mạng TCP/IP mặc định: 1433.

1.3. Git:
  - Phiên bản Git: >= 2.40.0.

1.4. Trình duyệt Web & Ví Web3:
  - Trình duyệt: Google Chrome, Microsoft Edge, Brave hoặc Firefox.
  - Tiện ích mở rộng (Extension): MetaMask Wallet (phiên bản mới nhất).

4. CÀI ĐẶT & CẤU HÌNH SQL SERVER, TẠO DATABASE, MIGRATION VÀ SEED
================================================================================
Thực hiện chính xác theo thứ tự 3 bước sau:

4.1. Bước 1: Tạo cấu trúc bảng cơ sở (Base Schema)
  - Mở công cụ SQL Server Management Studio (SSMS).
  - Kết nối vào SQL Server instance của bạn (ví dụ `localhost` hoặc `.\SQLEXPRESS`).
  - Mở tệp: `BookChainLibrary_SQLServer.sql` (nằm ở thư mục gốc của dự án).
  - Nhấn nút "Execute" (F5).
  - Tác vụ thực hiện:
    * Tạo cơ sở dữ liệu `BookChainLibrary` nếu chưa tồn tại.
    * Tạo 15 bảng nghiệp vụ chính: Users, Roles, UserRoles, Sessions, AuthorProfiles,
      Books, BookAuthors, BookFiles, CopyrightRecords, Reports, ReportActions,
      Wallets, BlockchainTransactions, Favorites, ReadingProgress.
    * Seed sẵn 3 vai trò hệ thống: READER, AUTHOR, ADMIN trong bảng dbo.Roles.
  - Kết quả mong đợi: Thông báo "BookChainLibrary schema script completed." (0 errors).

4.2. Bước 2: Chạy migration bảng mã mời tác giả (Author Invitations Migration)
  - Mở Terminal tại thư mục gốc dự án.
  - Chạy lệnh migration:
      npm run db:migrate
  - Lệnh tương ứng thực tế: `tsx server/db/runMigration.ts`
  - Tác vụ thực hiện: Đọc tệp `server/db/migrations/001_create_invitations.sql`, tạo
    2 bảng `dbo.AuthorInvitations` và `dbo.InvitationUses` kèm các chỉ mục (indexes).
  - Kết quả mong đợi:
      [Migration] Successfully executed: 001_create_invitations.sql

4.3. Bước 3: Nạp dữ liệu sách số mẫu (Seed Books)
  - Dữ liệu sách mẫu sẽ được tự động nạp khi server khởi động (nếu đã có ít nhất 1 tài khoản
    người dùng trong hệ thống để gán bút danh tác giả).
  - Hoặc bạn có thể chạy thủ công sau khi đăng ký tài khoản đầu tiên bằng lệnh:
      npx tsx server/db/seedBooks.ts
  - Tác phẩm được nạp gồm 3 cuốn sách kinh điển với tệp PDF thực tế và mã băm SHA-256 thật:
    1. "Đại Việt Sử Ký Toàn Thư — Bản Khảo Dị Quốc Sử Quán" (PUBLIC_READ)
    2. "Truyện Kiều — Khảo Luận Văn Bản Nôm Liễu Văn Đường 1871" (PUBLIC_DOWNLOAD)
    3. "The Architecture of Trustless Digital Archives" (PUBLIC_READ)

5. THIẾT LẬP TÀI KHOẢN THỬ NGHIỆM VÀ BOOTSTRAP ADMIN AN TOÀN
================================================================================
Hệ thống KHÔNG có tài khoản Admin hardcode sẵn mật khẩu trong CSDL để đảm bảo bảo mật.
Bạn thiết lập quản trị viên đầu tiên bằng cơ chế Bootstrap an toàn:

5.1. Bước 1: Khởi động server hoặc đăng ký tài khoản qua API/Giao diện
  - Cách A (Khuyên dùng):
    * Khởi chạy dự án (xem mục 8), mở trình duyệt tại `http://localhost:5173/login`.
    * Chuyển sang tab "Đăng ký" và tạo một tài khoản mới, ví dụ:
        Họ tên  : Quản Trị Viên
        Email   : admin@bookchain.io
        Mật khẩu: Password123!
  - Cách B (Qua lệnh curl / PowerShell API):
    Invoke-RestMethod -Uri "http://localhost:5000/api/auth/register" -Method Post `
      -ContentType "application/json" `
      -Body '{"email":"admin@bookchain.io","password":"Password123!","displayName":"Quản Trị Viên"}'

5.2. Bước 2: Nâng cấp tài khoản thành ADMIN qua lệnh CLI an toàn
  - Mở Terminal tại thư mục gốc dự án.
  - Chạy lệnh bootstrap admin:
      npm run bootstrap:admin -- admin@bookchain.io
  - Script thực thi: `server/scripts/bootstrapAdmin.ts`
  - Cơ chế bảo mật:
    * Tìm người dùng theo email chuẩn hóa.
    * Gán vai trò `ADMIN` vào bảng `dbo.UserRoles` với ghi nhận kiểm toán tự bootstrap.
    * Tuyệt đối không in mật khẩu, token hay private key ra màn hình.
    * Tính chất Idempotent: Nếu chạy lại cho cùng một email, hệ thống thông báo tài khoản
      đã là ADMIN mà không bị nhân bản bản ghi.
  - Kết quả mong đợi:
      ===============================================================
      ADMIN BOOTSTRAP RESULT: SUCCESS
      ===============================================================
      User ID:      <GUID>
      Email:        admin@bookchain.io
      Display Name: Quản Trị Viên
      Roles:        READER, ADMIN
      Status:       User [admin@bookchain.io] has been successfully granted the ADMIN role.
      ===============================================================

Hệ thống sử dụng mạng blockchain cục bộ Hardhat Node để phát triển và kiểm thử
toàn bộ các chức năng Web3 on-chain mà không tốn phí gas hay phụ thuộc internet.

6.1. Khởi chạy Hardhat Node (Mở Terminal 1):
  - Chạy lệnh:
      npm run contracts:node
  - Lệnh thực tế: `hardhat node`
  - Kết quả mong đợi:
      Node JSON-RPC khởi chạy tại: `http://127.0.0.1:8545/`
      Chain ID: 31337

  - QUAN TRỌNG: Giữ Terminal này mở liên tục trong suốt quá trình làm việc.

6.2. Triển khai Smart Contract lên Local Node (Mở Terminal 2):
  - Tại một cửa sổ Terminal mới, chạy lệnh:
      npm run contracts:deploy:local
  - Lệnh thực tế: `hardhat run scripts/deploy.cjs --network localhost`
  - Tác vụ tự động thực hiện:
    * Biên dịch contract `BookCopyrightRegistry.sol` (nếu cần).
    * Triển khai contract bằng tài khoản Account #0 (`0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266`).
    * Ghi lại biên lai triển khai vào: `deployments/localhost.json`.
    * Tự động cập nhật địa chỉ contract mới vào:
      - `src/contracts/deployedAddresses.json` (dành cho Frontend React).
      - `server/contracts/deployedAddresses.json` (dành cho Backend Express).
  - Kết quả mong đợi:

10. HƯỚNG DẪN KIỂM TRA CÁC LUỒNG NGHIỆP VỤ CHÍNH TRÊN GIAO DIỆN
================================================================================
Sau khi hệ thống đã khởi chạy, kiểm tra các luồng theo trình tự logic sau:

10.1. Luồng 1: Đăng nhập & Phân quyền RBAC (READER -> AUTHOR -> ADMIN)
  - Truy cập `http://localhost:5173/login`.
  - Đăng ký một tài khoản độc giả mới (READER).
  - Sau khi đăng nhập, kiểm tra thanh Navbar: Người dùng READER chỉ có menu "Khám phá", "Tác giả", "Cách thức hoạt động", "Xác minh" và nút "Hồ sơ". Nút kết nối ví không xuất hiện để tránh gây nhiễu.

10.2. Luồng 2: Quy trình Đăng ký Bút danh & Duyệt Tác giả (Author Approval)
  - Tại trang Hồ sơ cá nhân (`/profile`):
    * Độc giả điền form "Đăng ký bút danh tác giả" (Nhập Bút danh và Tiểu sử) -> Nhấn "Gửi hồ sơ xét duyệt".
    * Trạng thái hồ sơ chuyển sang màu hổ phách: `PENDING` (Đang chờ Quản trị viên xét duyệt).
    * Tài khoản chưa có quyền tạo sách (nếu truy cập `/author/studio` sẽ có banner thông báo trạng thái).
  - Đăng xuất, đăng nhập vào tài khoản ADMIN (`admin@bookchain.io`):
    * Truy cập Bảng điều khiển Quản trị (`/admin`) -> Chọn tab "DUYỆT TÁC GIẢ" (AUTHOR_REQUESTS).
    * Thấy yêu cầu của tác giả vừa gửi trong bảng danh sách.
    * Nhấn nút "Phê duyệt" (Approve) kèm ghi chú kiểm toán.
  - Đăng nhập lại tài khoản tác giả:
    * Trạng thái hồ sơ chuyển sang màu xanh lá: `VERIFIED` (Đã phê duyệt).
    * Tài khoản được tự động cấp vai trò `AUTHOR`.
    * Menu "Author Studio" xuất hiện trên Navbar và nút "Tạo tác phẩm" được mở khóa hoàn toàn.

10.3. Luồng 3: Quy trình Mã mời Tác giả (Author Invitations)
  - Tài khoản ADMIN vào `/admin` -> Chọn tab "MÃ MỜI TÁC GIẢ" (INVITATIONS).
  - Điền form: chọn thời hạn (ví dụ 30 ngày), số lượt dùng tối đa (1 lượt), ghi chú -> Nhấn "Tạo mã mời".
  - Hộp thoại hiển thị chuỗi mã mật mã định dạng `BKC-XXXX-YYYY-ZZZZ`.
  - Một độc giả khác có thể vào `/profile`, nhập chuỗi mã này vào ô "Đổi mã mời tác giả" -> Nâng cấp tức thì lên `AUTHOR`.

10.4. Luồng 4: Tạo Tác phẩm, Tải Tệp và Tăng Phiên bản (Author Studio)
  - Tác giả vào `/author/studio` -> Nhấn "Tạo tác phẩm mới".
  - Nhập Tiêu đề, Mô tả, Ngôn ngữ, URL Ảnh bìa -> Nhấn "Tạo tác phẩm".
  - Trong chi tiết sách, tải lên tệp bản thảo đầu tiên (PDF, EPUB, TXT).
  - Hệ thống tự động tính mã băm SHA-256 từ byte thực tế của tệp, lưu tệp vào `storage/books/` với Safe Storage Key, đặt `VersionNumber = 1` và `IsCurrent = 1`.
  - Khi tác giả tải lên bản thảo sửa đổi thứ hai: Hệ thống đặt `VersionNumber = 2`, cập nhật `IsCurrent = 1` cho bản mới và chuyển bản cũ thành `IsCurrent = 0`. Cả 2 phiên bản đều được lưu vết đầy đủ.

10.5. Luồng 5: Đăng ký Bản quyền Lên Blockchain (Blockchain Copyright Registration)
  - Tác giả kết nối ví MetaMask (chọn mạng Hardhat Local).
  - Tại trang tác phẩm trong Author Studio, chọn phiên bản tệp muốn đăng ký -> Nhấn "Đăng ký bản quyền".
  - Nhập Tuyên bố tác quyền (Claim Statement).
  - Nhánh A (Nếu ví đang kết nối là Account #0 có quyền Registrar):
    * MetaMask hiển thị popup xác nhận giao dịch -> Nhấn "Xác nhận".
    * Smart contract thực thi hàm `registerCopyright()`.
  - Nhánh B (Nếu ví đang kết nối là ví tác giả thông thường):
    * Giao diện cung cấp tùy chọn "Ủy quyền Registrar Relay phát sóng".
    * Nhấn nút ủy quyền -> Backend Relay Signer phát sóng giao dịch thay mặt tác giả; địa chỉ ví của tác giả vẫn được ghi bất biến vào trường `authorWallet` on-chain.
  - Sau khi giao dịch được xác nhận (1 confirmation): Trạng thái bản ghi chuyển thành `ON_CHAIN`, lưu vết TxHash và số khối.

10.6. Luồng 6: Xác minh Bản quyền Độc lập (Archival Verification)
  - Truy cập trang `/verify`.
  - Cách A (Kéo thả tệp): Kéo thả bất kỳ tệp sách nào vào ô tải lên. Trình duyệt tự tính mã băm SHA-256 ngay trên client qua Web Crypto API, sau đó truy vấn Smart Contract `contract.verifyHash()` và CSDL SQL Server.
  - Cách B (Tra cứu theo Hash / Record ID): Nhập chuỗi SHA-256 hex hoặc mã bản ghi.
  - Kết quả hiển thị: Chứng chỉ Lưu trữ (Archival Certificate) gồm Trạng thái On-Chain (`ACTIVE`), Record ID, Mã băm SHA-256, Ví tác giả, Số khối, và đối soát toàn vẹn byte tệp trên máy chủ.

10.7. Luồng 7: Xử lý Khiếu nại, Tranh chấp & Cầu dao Khẩn cấp (Disputes & Circuit Breaker)
  - Độc giả truy cập trang chi tiết sách `/book/:id` -> Nhấn "Khiếu nại bản quyền".
  - Chọn lý do vi phạm (ví dụ: Đạo văn/sao chép), nhập mô tả chi tiết -> Gửi khiếu nại.
  - Admin vào `/admin` -> Chọn tab "KHIẾU NẠI & TRANH CHẤP" (DISPUTES):
    * Xem bằng chứng và lịch sử xử lý (Audit Timeline).
    * Nhấn "Kích hoạt Tranh chấp On-chain": Smart contract đổi trạng thái sang `DISPUTED`.
    * Sau khi xác minh, Admin có thể:
      - "Khôi phục Bản quyền": Smart contract hoàn nguyên về `ACTIVE`.
      - Hoặc "Thu hồi Vĩnh viễn": Smart contract chuyển sang `REVOKED`.
  - Tab "GOVERNANCE": Admin có thể gạt công tắc "Circuit Breaker" (Tạm dừng khẩn cấp Smart Contract qua `pause()`). Khi đang tạm dừng, mọi giao dịch đăng ký mới on-chain đều bị từ chối an toàn.

11. DANH MỤC SỰ CỐ THƯỜNG GẶP (TROUBLESHOOTING) VÀ CÁCH XỬ LÝ
================================================================================

11.1. Lỗi: "Database connection failed / Failed to connect to localhost:1433"
  - Nguyên nhân: SQL Server chưa khởi chạy, hoặc dịch vụ TCP/IP bị tắt trong SQL Server Configuration Manager.
  - Cách khắc phục:
    1. Mở `services.msc` -> Tìm `SQL Server (MSSQLSERVER)` hoặc `SQL Server (SQLEXPRESS)` -> Chọn "Start" / "Restart".
    2. Mở "SQL Server Configuration Manager" -> Chọn "SQL Server Network Configuration" -> "Protocols for MSSQLSERVER" -> Đảm bảo `TCP/IP` đang ở trạng thái `Enabled`.
    3. Nhấp đúp vào `TCP/IP` -> Tab `IP Addresses` -> Cuộn xuống `IPAll` -> Đảm bảo `TCP Port` là `1433`.
    4. Khởi động lại dịch vụ SQL Server.

11.2. Lỗi: "Login failed for user 'sa'" / Sai mật khẩu .env
  - Nguyên nhân: Mật khẩu `DB_PASSWORD` trong file `.env` không khớp với mật khẩu tài khoản `sa` của bạn.
  - Cách khắc phục: Mở SSMS, đăng nhập bằng Windows Authentication, chuột phải vào `Security` -> `Logins` -> `sa` -> Đặt lại mật khẩu mới. Cập nhật lại mật khẩu này vào file `.env`.

11.3. Lỗi: Cổng mạng bị chiếm dụng (Port 5000, 5173 hoặc 8545)
  - Biểu hiện: `Error: listen EADDRINUSE: address already in use :::5000`
  - Cách khắc phục trên Windows PowerShell:
    * Tìm Process ID (PID) đang chiếm cổng (ví dụ cổng 5000):
        Get-Process -Id (Get-NetTCPConnection -LocalPort 5000).OwningProcess
    * Đóng tiến trình đó:
        Stop-Process -Id <PID> -Force

11.4. Lỗi: "Contract address not found / CALL_EXCEPTION on smart contract"
  - Nguyên nhân: Bạn vừa khởi động lại `npm run contracts:node`, khiến toàn bộ dữ liệu node local bị reset về Block 0 và hợp đồng cũ bị mất.
  - Cách khắc phục:
    Chỉ cần chạy lại lệnh triển khai:
      npm run contracts:deploy:local
    Lệnh này sẽ tự động deploy lại và cập nhật địa chỉ contract mới vào toàn bộ cấu hình client/server.

11.5. Lỗi: MetaMask báo "Nonce too high" hoặc giao dịch bị treo (Pending)
  - Nguyên nhân: Node Hardhat local bị khởi động lại trong khi ví MetaMask vẫn lưu số đếm nonce cũ của các phiên trước.
  - Cách khắc phục trong MetaMask:
    Vào MetaMask -> Nhấn vào biểu tượng tài khoản (tròn trên cùng góc phải) -> "Cài đặt" (Settings) -> "Nâng cao" (Advanced) -> Nhấn nút "Xóa dữ liệu tab hoạt động" (Clear activity tab data) hoặc "Đặt lại tài khoản" (Reset account). Việc này KHÔNG làm mất tiền hay private key mà chỉ xóa lịch sử nonce bị lệch.

11.6. Lỗi: MetaMask báo "Wrong Network"
  - Khắc phục: Nhấn nút chuyển mạng trên giao diện ứng dụng hoặc chuyển mạng thủ công trong MetaMask về "Hardhat Local" (Chain ID 31337).
