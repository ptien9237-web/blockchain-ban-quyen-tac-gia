================================================================================
BOOKCHAIN LIBRARY — PROJECT NOTES & RUNTIME ARCHITECTURE
================================================================================

1. MỤC TIÊU DỰ ÁN
BookChain Library là hệ thống Thư viện số cao cấp kết hợp Sổ cái đăng ký và xác minh
bản quyền tác phẩm sách bất biến (Digital Library & Blockchain Copyright Registry).
Triết lý thiết kế cốt lõi:
  "LIBRARY FIRST, COPYRIGHT SECOND, BLOCKCHAIN UNDERNEATH."
Phong cách giao diện: "Archival Reading Room" (Phòng đọc Học thuật Lưu trữ), 
tĩnh lặng, trang nhã, không chạy theo phong cách sàn giao dịch crypto thương mại.

2. KIẾN TRÚC HIỆN TẠI (SAU BƯỚC 02)
- Frontend: Single Page Application (SPA) phát triển bằng React 19 + TypeScript + Vite.
  Sử dụng Vanilla CSS và Design Tokens định nghĩa tập trung tại src/index.css.
  Hỗ trợ song ngữ Anh/Việt (I18nContext) và chế độ Sáng/Tối (ThemeContext).
  Tích hợp "Archival Reading Room" trực quan: Modal PDF Reader trực tiếp, trình chuyển đổi
  phiên bản (version switcher), công cụ tính SHA-256 trên trình duyệt (Web Crypto API)
  kết hợp đối soát với Sổ cái cơ sở dữ liệu và xác minh tính toàn vẹn byte tệp trên đĩa máy chủ.
- Backend: RESTful API Server phát triển bằng Express + TypeScript (chạy bằng tsx).
  Tổ chức theo kiến trúc phân tầng chuẩn:
    Routes -> Controllers -> Services -> Storage Provider / Repositories -> Database (MSSQL Connection Pool).
- Lưu trữ Tệp (Storage Layer):
  Kiến trúc trừu tượng hóa StorageProvider qua giao diện IStorageProvider:
  * LocalStorageProvider: Lưu trữ tệp trên phân vùng máy chủ cục bộ (mặc định tại storage/books/).
  * Chuẩn hóa tên tệp an toàn (Safe File Key): YYYYMMDD_<uuid>.<ext> ngăn ngừa Path Traversal.
  * Tính mã băm SHA-256 từ chuỗi byte nhị phân thực tế của tệp nhận được (Node.js crypto).
  * Đối soát tính toàn vẹn (Integrity Verification): đọc lại byte tệp trên đĩa và so sánh với
    mã băm đã ghi nhận trong CSDL để phát hiện can thiệp giả mạo.
  * Chuẩn bị sẵn sàng mở rộng sang IpfsStorageProvider ở các giai đoạn tiếp theo.
- Database: Microsoft SQL Server 2025 (Database name: BookChainLibrary).
  Sử dụng các bảng thực tế:
    dbo.Users, dbo.Roles, dbo.UserRoles, dbo.Sessions, dbo.AuthorProfiles,
    dbo.Books, dbo.BookAuthors, dbo.BookFiles.
- Kiểm soát Truy cập & Tác quyền (Access Control & Authorship):
  * Chỉ tác giả sở hữu (Primary Author hoặc Co-Author) mới có quyền chỉnh sửa sách,
    thêm đồng tác giả, tải lên phiên bản mới và chuyển đổi trạng thái xuất bản (DRAFT, PUBLISHED, ARCHIVED).
  * Chặn IDOR nghiêm ngặt tại Backend (kiểm tra liên kết User -> AuthorProfile -> BookAuthors).
  * Phân quyền đọc/tải tệp theo 3 mức độ (AccessLevel):
    - PRIVATE: Chỉ tác giả và Quản trị viên được xem nội dung và tải về.
    - PUBLIC_READ: Cho phép bạn đọc xem/đọc trực tuyến qua Reader nhưng chặn tải file gốc (HTTP 403).
    - PUBLIC_DOWNLOAD: Cho phép bạn đọc cả đọc trực tuyến lẫn tải file gốc.

6. CÁC API HOÀN THIỆN ĐẾN HẾT BƯỚC 02
- Health & System:
  * GET  /api/health                             - Kiểm tra trạng thái server và kết nối SQL Server
- Authentication:
  * POST /api/auth/register                     - Đăng ký tài khoản (hashing bcrypt, gán role READER)
  * POST /api/auth/login                        - Đăng nhập (trả về token và gán HttpOnly cookie)
  * POST /api/auth/logout                       - Đăng xuất (thu hồi phiên trong dbo.Sessions)
  * GET  /api/auth/me                           - Lấy thông tin tài khoản đang đăng nhập
- User Profile & Author Credentials:
  * GET  /api/users/profile                     - Xem chi tiết hồ sơ cá nhân
  * PUT  /api/users/profile                     - Cập nhật DisplayName, AvatarUrl
  * POST /api/users/author-profile              - Đăng ký bút danh & tiểu sử, cấp role AUTHOR
- Book Catalog & Management (MỚI BƯỚC 02):
  * GET  /api/books                             - Tra cứu danh mục sách công khai (tìm kiếm, lọc, phân trang)
  * GET  /api/books/my                          - Lấy danh sách tác phẩm của tác giả đang đăng nhập
  * GET  /api/books/:id                         - Lấy chi tiết sách (thông tin tác giả, tệp hiện hành, trạng thái)
  * POST /api/books                             - Tạo tác phẩm mới (Transactional: tạo Book + liên kết Primary Author)
  * PUT  /api/books/:id                         - Cập nhật metadata sách (kiểm tra quyền sở hữu IDOR)
  * PATCH /api/books/:id/status                 - Cập nhật trạng thái xuất bản (DRAFT, PUBLISHED, UNLISTED, ARCHIVED)
  * POST /api/books/:id/authors                 - Thêm đồng tác giả (CO_AUTHOR, EDITOR, TRANSLATOR)
- Book Files & Versioning (MỚI BƯỚC 02):
  * POST /api/books/:id/files                   - Tải lên phiên bản tệp mới (tính SHA-256 byte thật, tăng VersionNumber, cập nhật IsCurrent)
  * GET  /api/books/:id/files                   - Xem lịch sử phiên bản tệp của tác phẩm (yêu cầu quyền sở hữu hoặc xem phiên bản công khai)
  * GET  /api/books/:id/files/:fileId           - Lấy metadata tệp cụ thể
  * GET  /api/books/:id/files/:fileId/read      - Đọc trực tuyến tệp sách (hỗ trợ Content-Type application/pdf, chặn nếu PRIVATE và không có quyền)
  * GET  /api/books/:id/files/:fileId/download  - Tải file gốc về máy (chặn nếu mức truy cập là PRIVATE hoặc PUBLIC_READ đối với người không có quyền tác giả)
  * GET  /api/books/:id/files/:fileId/verify    - Đối soát toàn vẹn SHA-256: đọc lại tệp trên đĩa và so khớp với mã băm trong CSDL
  * GET  /api/books/verify-hash/:hash           - Tra cứu tác phẩm và tệp theo mã băm SHA-256 từ Sổ cái hệ thống

7. LUỒNG NGHIỆP VỤ CỐT LÕI (BƯỚC 02)
- Luồng tạo sách và xác thực tác giả:
  1. Người dùng phải đăng ký Author Profile để sở hữu vai trò AUTHOR.
  2. Gửi request POST /api/books kèm Title, Description, CoverUrl, LanguageCode.
  3. Backend mở Transaction: tạo bản ghi trong dbo.Books, tự động thêm liên kết trong dbo.BookAuthors
     với AuthorProfileId của người dùng và ContributionRole = 'PRIMARY_AUTHOR', DisplayOrder = 1.
- Luồng tải lên tệp và quản lý phiên bản:
  1. Tác giả gửi file (PDF, EPUB, TXT) qua form multipart/form-data lên POST /api/books/:id/files.
  2. Middleware upload kiểm tra dung lượng (<= 50MB) và MIME type / định dạng tệp.
  3. LocalStorageProvider lưu tệp an toàn vào thư mục storage/books/, đồng thời tính toán
     mã băm SHA-256 trực tiếp từ chuỗi byte nhị phân của tệp đã lưu.
  4. Backend mở Transaction trên SQL Server:
     - Lấy VersionNumber lớn nhất hiện có của cuốn sách.
     - Đặt VersionNumber mới = MAX + 1 (mặc định 1 cho file đầu tiên).
     - Cập nhật tất cả các phiên bản trước đó thành IsCurrent = 0.
     - Chèn bản ghi phiên bản mới vào dbo.BookFiles với IsCurrent = 1, Sha256Hash thật và AccessLevel.
- Luồng kiểm soát quyền đọc và tải (Access Level Enforcement):
  * GET /api/books/:id/files/:fileId/read:
    - PRIVATE: Chỉ tác giả của sách hoặc ADMIN mới được đọc (HTTP 403 nếu vi phạm).
    - PUBLIC_READ / PUBLIC_DOWNLOAD: Cho phép đọc trực tuyến dưới dạng stream nhị phân (inline).
  * GET /api/books/:id/files/:fileId/download:
    - PRIVATE: Chỉ tác giả hoặc ADMIN mới được tải file gốc.
    - PUBLIC_READ: Chặn tải file gốc đối với độc giả thông thường (HTTP 403, báo lỗi chỉ cho phép đọc trực tuyến).
    - PUBLIC_DOWNLOAD: Cho phép tải file gốc về máy dưới dạng attachment.
- Luồng tính và đối soát SHA-256:
  1. Tại Frontend trang Verify (/verify): Người dùng chọn tệp cục bộ bất kỳ. Trình duyệt tính mã băm
     SHA-256 tức thì bằng Web Crypto API (SubtleCrypto.digest) từ byte thực tế của tệp.
  2. Gửi mã băm lên Backend GET /api/books/verify-hash/:hash để tra cứu trên Sổ cái CSDL SQL Server.
  3. Nếu tìm thấy tệp, trang Verify gọi tiếp endpoint GET /api/books/:bookId/files/:fileId/verify
     để máy chủ đọc lại byte tệp lưu trữ trên đĩa và so khớp SHA-256 thực tế, trả về kết quả đối soát toàn vẹn.

BƯỚC 02.1 — ADMIN BOOTSTRAP & AUTHOR INVITATION SYSTEM
================================================================================

1. NGUYÊN TẮC PHÂN QUYỀN RBAC (READER / AUTHOR / ADMIN)
- READER (Mặc định khi đăng ký mới):
  * Được phép: Đăng nhập/đăng xuất, xem danh mục sách, đọc trực tuyến sách công khai, cập nhật hồ sơ cá nhân.
  * Được phép: Nhập mã mời tác giả hợp lệ để nâng quyền lên AUTHOR.
  * Không được phép: Tạo/sửa sách, tải lên bản thảo tác giả, tạo mã mời hoặc truy cập các API / trang quản trị.
- AUTHOR (Được cấp sau khi nhập mã mời hợp lệ):
  * Sở hữu đầy đủ quyền của READER.
  * Được phép: Tạo và quản lý tác phẩm của chính mình, thêm đồng tác giả, tải lên các phiên bản file, hoàn thiện bút danh tác giả.
  * Không được phép: Tạo mã mời, thu hồi mã mời hoặc truy cập API quản trị.
- ADMIN (Quản trị viên nền tảng):
  * Khởi tạo thông qua lệnh CLI có kiểm soát, KHÔNG có endpoint đăng ký công khai.
  * Được phép: Truy cập Admin Dashboard (/admin), xem danh sách mã mời, tạo mã mời tác giả mới, thu hồi mã mời, giám sát số lượt sử dụng.

2. CƠ CHẾ BOOTSTRAP ADMIN AN TOÀN
- File thực thi: `server/scripts/bootstrapAdmin.ts` (Script CLI chạy thủ công, không tự động chạy khi khởi động server).
- Lệnh chạy:
    npm run bootstrap:admin -- <email>
- Cơ chế bảo mật:
  * Kiểm tra vai trò ADMIN tồn tại trong dbo.Roles.
  * Tìm tài khoản người dùng theo email chuẩn hóa (trim, lowercase).
  * Nếu tài khoản đã có vai trò ADMIN: Báo thông tin an toàn, thoát không ghi trùng (Idempotent).
  * Nếu chưa có vai trò: Mở transaction gán bản ghi vào dbo.UserRoles.
  * Không hardcode mật khẩu, không in session token hay secret nhạy cảm ra màn hình.
  * Tài khoản ADMIN đầu tiên đã được xác minh trên local: minhtri@bookchain.io.

3. HỆ THỐNG MÃ MỜI TÁC GIẢ (AUTHOR INVITATION SYSTEM)
- Sinh mã an toàn bằng CSPRNG (Node.js crypto.randomBytes):
  * Định dạng: BKC-XXXX-YYYY-ZZZZ (Ví dụ: BKC-A1B2-C3D4-E5F6).
  * Độ khó đoán cao, chống brute-force.
- Lưu trữ an toàn bằng mã băm SHA-256 (CodeHash CHAR(64)):
  * CSDL KHÔNG lưu chuỗi mã gốc.
  * Khi tạo mã thành công, chuỗi mã gốc chỉ được trả về một lần duy nhất trong phản hồi JSON để Admin sao chép.
  * Danh sách mã mời (/api/admin/invitations) chỉ hiển thị thời hạn, số lượt đã dùng, tối đa và trạng thái, tuyệt đối không lộ CodeHash hay mã gốc.
- Cơ chế chống vượt lượt (Concurrency Control):
  * Sử dụng SQL Server Transaction với khóa dòng (UPDLOCK, ROWLOCK) trên bảng dbo.AuthorInvitations.
  * Kiểm tra đồng thời: Status = 'ACTIVE', ExpiresAt > GETDATE(), UsedCount < MaxUses.
  * Nếu đạt điều kiện: Tăng UsedCount, nếu UsedCount = MaxUses thì cập nhật Status = 'EXHAUSTED'.
  * Ghi bản ghi kiểm toán vào dbo.InvitationUses (UserId, UsedAt, IpAddress, UserAgent).
  * Cấp vai trò AUTHOR cho người dùng trong dbo.UserRoles (nếu người dùng chưa có vai trò AUTHOR).
  * Nếu người dùng đã là AUTHOR: Từ chối đổi mã, không tiêu thụ lượt sử dụng.
  * Nếu người dùng là ADMIN: Đổi mã an toàn, giữ nguyên vai trò ADMIN không bị hạ cấp.

4. BẢNG DỮ LIỆU CSDL MỚI (MIGRATION: 001_create_invitations.sql)
- `dbo.AuthorInvitations`:
  * InvitationId (UNIQUEIDENTIFIER, PK)
  * CodeHash (CHAR(64), UNIQUE, NOT NULL)
  * CreatedByUserId (UNIQUEIDENTIFIER, FK -> Users)
  * ExpiresAt (DATETIME2, NOT NULL)
  * MaxUses (INT, NOT NULL, DEFAULT 1)
  * UsedCount (INT, NOT NULL, DEFAULT 0)
  * Status (NVARCHAR(20), NOT NULL, DEFAULT 'ACTIVE': ACTIVE, REVOKED, EXPIRED, EXHAUSTED)
  * RevokedAt (DATETIME2, NULL)
  * RevokedByUserId (UNIQUEIDENTIFIER, FK -> Users, NULL)
  * Note (NVARCHAR(255), NULL)
  * CreatedAt (DATETIME2, NOT NULL)
- `dbo.InvitationUses`:
  * InvitationUseId (UNIQUEIDENTIFIER, PK)
  * InvitationId (UNIQUEIDENTIFIER, FK -> AuthorInvitations)
  * UserId (UNIQUEIDENTIFIER, FK -> Users)
  * UsedAt (DATETIME2, NOT NULL)
  * IpAddress (NVARCHAR(45), NULL)
  * UserAgent (NVARCHAR(255), NULL)

6. GIAO DIỆN NGƯỜI DÙNG (FRONTEND)
- Giao diện Admin Dashboard (/admin):
  * Thẻ tổng quan số lượng mã mời, trạng thái hệ thống.
  * Biểu mẫu tạo mã mời với tùy chọn thời hạn (7, 14, 30, 90, 180, 365 ngày), số lượt sử dụng tối đa và ghi chú.

  * Bảo vệ giao diện: Điều hướng về /login hoặc từ chối truy cập nếu không phải ADMIN.
- Trang Hồ sơ cá nhân (/profile):
  * Người dùng READER: Hiển thị hộp "Trở thành tác giả" cho phép nhập mã mời để nâng quyền.
  * Sau khi đổi thành công: Tự động refreshUser() từ /api/auth/me, lập tức cập nhật vai trò sang AUTHOR và mở khóa khu vực quản lý bút danh / tác phẩm.
  * Người dùng AUTHOR: Hiển thị thông tin hồ sơ tác giả đã kích hoạt.
  * Người dùng ADMIN: Hiển thị huy hiệu ADMIN và liên kết nhanh đến Bảng điều khiển Quản trị.
- Thanh điều hướng (Navbar):
  * Hiển thị biểu tượng và liên kết Quản trị (/admin) khi tài khoản sở hữu vai trò ADMIN.
  * Hỗ trợ đầy đủ song ngữ Tiếng Việt (VI) và Tiếng Anh (EN), tương thích chế độ Giao diện Sáng/Tối.

================================================================================
BƯỚC 03 — SMART CONTRACT & BLOCKCHAIN COPYRIGHT REGISTRY
================================================================================

1. NGUYÊN TẮC KIẾN TRÚC & PHÂN TÁCH DỮ LIỆU
- Triết lý: "Library First, Copyright Second, Blockchain Underneath".
- SQL Server quản lý toàn bộ dữ liệu nghiệp vụ: sách, tác giả, file nhị phân, quyền đọc/tải, lịch sử phiên bản.
- Blockchain (Ethereum Sepolia / Hardhat Local) lưu trữ chứng cứ bất biến:
  * RecordId (bytes32): Định danh duy nhất của bản ghi bản quyền.

3. TIỆN ÍCH MẬT MÃ VÀ CHUẨN HÓA SHA-256 (TYPESCRIPT <-> SOLIDITY)
- SHA-256 thực tế từ byte nội dung tệp (64 hex characters) được chuẩn hóa sang Solidity bytes32:
  * TypeScript: sha256ToBytes32(hex) => "0x" + clean_64_hex_lowercase (32 bytes).
  * Ngược lại: bytes32ToSha256(bytes32) => 64_hex_lowercase.
  * UUID chuyển sang bytes32: uuidToBytes32(uuid) => "0x" + 32_zeros + clean_32_hex.
- Đảm bảo tính nhất quán byte-for-byte 100% giữa Node.js crypto và Solidity bytes32.
